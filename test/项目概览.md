# 电商平台重构项目概览

## 背景

本次重构旨在解决现有系统在高并发场景下的性能瓶颈，同时将单体服务拆分为微服务架构，提升系统的可维护性和扩展性。

核心目标：

- 支撑日活 500 万用户的访问规模
- 核心链路响应时间 P99 降至 200ms 以内
- 服务可用性达到 99.95%

---

## 整体架构

### 前端层

- **Web 端**：React 18 + Vite，SSR 渲染首屏
- **移动端**：React Native，复用业务逻辑层
- **BFF 层**：Node.js，聚合下游接口，处理前端差异化需求

### 服务层

#### 核心业务服务

- 用户服务（user-service）
- 商品服务（product-service）
- 订单服务（order-service）
- 支付服务（payment-service）
- 库存服务（inventory-service）

#### 基础设施服务

- 网关（API Gateway）
- 配置中心（Config Center）
- 注册中心（Service Registry）
- 链路追踪（Tracing）

### 数据层

- MySQL 8.0（主从复制 + 读写分离）
- Redis 7.0（缓存、分布式锁、消息队列）
- Elasticsearch 8.x（商品搜索、日志分析）
- OSS（图片、文件存储）

## 风险与依赖

### 已识别风险

1. **数据迁移风险**：旧库表结构与新服务模型存在差异，需要双写过渡期。
2. **分布式事务复杂度**：订单创建涉及库存、优惠券、积分多个服务，需引入 Saga 模式。
3. **缓存雪崩**：商品缓存集中过期可能导致数据库压力骤增，需错峰 TTL 策略。

### 外部依赖

- 支付宝/微信支付接口联调窗口（需提前预约）
- 短信服务商 API 升级（计划 Week 3 完成迁移）

## 团队分工

> 各服务负责人对本服务的接口设计、数据库 Schema、测试覆盖率和线上稳定性负责。

- **架构组**：整体技术选型、规范制定、跨服务问题协调
- **业务组**：各服务功能开发、单元测试、联调
- **QA 组**：集成测试用例、性能测试、回归验证
- **运维组**：基础设施、部署流水线、线上巡检

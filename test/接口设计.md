# 订单服务接口设计
## 1. 创建订单
### 请求

```http
POST /api/v2/orders
Authorization: Bearer <token>
Content-Type: application/json
```


```json
{
  "userId": "u_123456",
  "items": [
    { "skuId": "sku_001", "quantity": 2, "price": 9900 },
    { "skuId": "sku_008", "quantity": 1, "price": 29900 }
  ],
  "addressId": "addr_789",
  "couponCode": "SUMMER20",
  "remark": "请尽快发货"
}
```

### 响应

**成功（201）**


```json
{
  "code": 0,
  "data": {
    "orderId": "ord_20240601_8823",
    "status": "PENDING_PAYMENT",
    "totalAmount": 49700,
    "discountAmount": 2000,
    "payableAmount": 47700,
    "expireAt": "2024-06-01T12:30:00Z"
  }
}
```


**失败示例**


| HTTP 状态码 | code | 场景 |
| --- | --- | --- |
| 400 | 1001 | 参数校验失败 |
| 400 | 1002 | 库存不足 |
| 400 | 1003 | 优惠券已使用或不存在 |
| 401 | 2001 | Token 过期或无效 |
| 500 | 9999 | 服务内部异常 |

## 2. 查询订单详情

```http
GET /api/v2/orders/{orderId}
Authorization: Bearer <token>
```

### 订单状态流转

```
PENDING_PAYMENT
    ↓ 用户支付
PAID
    ↓ 仓库确认
SHIPPED
    ↓ 物流签收
COMPLETED
```


取消分支：

- `PENDING_PAYMENT` → 超时未支付 → `CANCELLED`
- `PENDING_PAYMENT` → 用户主动取消 → `CANCELLED`
- `PAID` → 用户申请退款 → `REFUNDING` → `REFUNDED`
## 3. 幂等设计说明
- 所有写操作均通过 `X-Idempotency-Key` 头实现幂等：

  ```http
  POST /api/v2/orders
  X-Idempotency-Key: client-generated-uuid-v4
  ```

  - Key 有效期 **24 小时**，过期后相同 Key 视为新请求。
  - 服务端以 Redis SETNX 存储 Key → 响应结果的映射。
  - 如果首次请求处理中，后续相同 Key 的请求返回 `202 Accepted`，客户端轮询查询。
## 4. 字段说明
### OrderItem

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `skuId` | string | 是 | 商品 SKU ID |
| `quantity` | integer | 是 | 购买数量，最小 1，最大 99 |
| `price` | integer | 是 | 下单时快照价格，单位：分 |

### Address

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 收货人姓名 |
| `phone` | string | 手机号（脱敏存储） |
| `province` | string | 省 |
| `city` | string | 市 |
| `district` | string | 区/县 |
| `detail` | string | 详细地址 |

## 5. 注意事项

> **重要**：价格以服务端为准，客户端传入的 `price` 仅用于前端快照展示，下单时服务端会重新从商品服务取价。如果价格变动超过 5%，下单接口返回 `1004 价格已变动`，前端需提示用户确认。

- 单笔订单最多 **50** 个 SKU。
- 单个 SKU 数量上限 **99**。
- 订单备注 `remark` 最长 **200** 字。

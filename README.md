# CC MD MindMap

> AI 给你生成了一千行文档，你却要花两小时找到那三个关键点。CC MD MindMap 把线性文本变成可导航的思维导图，让 review 从头读到尾变成按图索骥。

你好，我是测试蔡坨坨。

最近在阅读 AI 生成的文档时十分痛苦，于是 Vibe Coding 了一个小工具——一款 Markdown 驱动的可视化脑图编辑器，用于文档 review、结构梳理和知识整理。

- **纯前端模式**：直接打开 `md-mindmap.html`，无需任何部署，开箱即用。
- **服务模式**：启动 `ai-proxy.js` 后通过浏览器访问，在纯前端基础上增加 AI 对话能力。

## 1. 背景

AI 批量生成的 Markdown 文档在人工阅读和 review 中存在几个常见痛点：

- 文档多且长，难以快速建立全局结构认知。
- 历史逻辑、新增逻辑、异常分支混在线性文本里，上下翻找成本高。
- 缺少 review 状态管理，无法在文档上直接标记节点进度和结论。

CC MD MindMap 通过思维导图将 Markdown 转为可导航的结构化视图，并支持节点状态标记，帮助用户降低长文档的阅读和 review 成本。

**Markdown 仍是唯一数据源**，导图与源码实时联动，无需维护两份文件。

## 2. 产品对比

| 方案 | 优点 | 不足 |
|---|---|---|
| 直接阅读 Markdown | 结构清晰，编辑友好 | 长文档阅读成本高，难以建立全局结构认知 |
| XMind 导入 Markdown | 脑图直观，展示效果好 | 产生第二份文件，与 Markdown 持续同步成本高，转换可能丢失格式 |
| markmap-vscode 插件 | 实时渲染脑图，开发者友好 | 仅预览，不支持在导图上编辑、标记状态、拖拽结构 |
| Notion / Confluence | 功能完整，协作能力强 | 需要在线服务，无法直接使用本地 Markdown 文件 |
| Obsidian | 本地文件，插件生态丰富 | 脑图能力依赖插件，与 Markdown 编辑流程割裂 |
| **CC MD MindMap** | Markdown 唯一内容源，导图与源码实时联动，节点状态标记，单文件本地运行 | Markdown 语法支持范围有限，依赖浏览器文件系统能力 |

## 3. 界面组成

| 区域 | 功能 |
|---|---|
| 顶部工具栏 | 打开文件/文件夹、撤销/重做、保存、标识节点导航、主题切换、状态统计、源码面板开关 |
| 左侧文件树 | 展示已加载的 Markdown 文件和文件夹，支持展开/收起、新建、删除、移除 |
| 中间导图画布 | 展示解析后的节点结构，支持选择、编辑、标记状态、拖拽、缩放、平移、展开/收起 |
| 右侧源码面板 | 源码编辑、渲染预览或分栏视图，与导图双向联动 |

## 4. 核心功能

### 4.1 打开文件

- 支持打开单个或多个 `.md` / `.markdown` 文件，也支持整个文件夹（递归读取）。
- 支持拖拽文件或文件夹到页面加载。
- Chromium 系浏览器优先使用 File System Access API，可直接写回原文件；其他浏览器通过浏览器缓存或下载保存。
- 使用 IndexedDB 记录文件句柄，localStorage 记录项目快照和偏好。

### 4.2 Markdown 解析规则

| Markdown 元素 | 导图节点 |
|---|---|
| `#` ~ `######` 标题 | 对应层级节点 |
| 无序/有序列表 | 子节点，保留缩进层级 |
| 普通段落 | 当前标题下的文本节点 |
| 代码块（` ``` ` / `~~~`） | 独立节点，保留语言标识和内容 |
| 表格 | 表格节点，表头和数据行可展示 |
| 状态 emoji（`✅` `❌` `⏳`） | 自动识别为节点状态 |

表格单元格中的 `<br>` 在解析时转换为换行，保存时按表格规则处理。

### 4.3 导图浏览

- 根据 Markdown 层级自动布局，连线呈现父子关系。
- 节点展开/收起，收起后重新布局减少空白。
- 画布拖拽平移、按钮/滚轮缩放、居中/重置视图。
- 锁定缩放后，使用垂直滚动条浏览长导图。

### 4.4 节点编辑

直接在导图上编辑，结果实时同步到 Markdown 源码。

| 操作 | 方式 |
|---|---|
| 编辑节点文本 | 双击节点，或选中后按 `Enter` |
| 新增子节点 | 选中后按 `Tab` |
| 删除节点 | 选中后按 `Delete` / `Backspace` |
| 取消选择 | `Escape` |
| 拖拽调整结构 | 拖到节点中部成为子节点；拖到上/下边缘插入到该节点前/后（同级排序） |

节点内联渲染行内代码、粗体、斜体、删除线、链接。拖拽后根据父节点类型自动调整 Markdown 输出（标题或列表项）。根节点不可删除。

### 4.5 节点状态标记

支持三种节点状态，写回 Markdown 时用 emoji 保留：

| 状态 | emoji | 快捷键 | 含义 |
|---|---|---|---|
| 完成 | `✅` | `1` | 已确认完成或通过 |
| 问题 | `❌` | `2` | 存在问题或需要修复 |
| 待处理 | `⏳` | `3` | 待执行或重点关注 |

状态以节点左侧色条 + 节点内标识 + 顶部统计数字三处体现。支持按钮定位上一个/下一个已标识节点（自动展开祖先节点并滚动到可见区域）。

**批量操作**：

- `Cmd/Ctrl + 点击` 节点加入/移出多选；多选时高亮主选 + 次选。
- 选中（单选或多选）后按 `1`/`2`/`3` 批量打状态，按 `0` 清除；同样可点击节点旁的状态按钮。
- 状态写回 Markdown 时仍保持原始顺序，不影响源码结构。

**节点备注**：
- 点击节点旁的备注按钮（✎）或备注圆点，弹出输入框写下补充说明。
- 备注序列化为 HTML 注释 `<!-- note: ... -->`，紧跟节点行，不影响阅读 Markdown。

**Review 摘要**：工具栏的"摘要"按钮打开右侧浮动面板，按状态分组列出当前文件所有已标识节点，并显示祖先路径，点击直接跳转。

**多文件汇总**：左侧文件树每行右侧显示该文件的 ✅/❌/⏳ 数量徽章（已加载文件实时统计；其他文件按 Markdown 中的 emoji 频次估算）。

### 4.6 搜索与过滤

顶部工具栏内置搜索框（`Cmd/Ctrl + F` 聚焦）：

- 关键词大小写不敏感，支持节点正文和表格单元格匹配。
- 状态过滤：点击 ✅ / ❌ / ⏳ 三个 chip 切换，多选取并集。
- 命中节点高亮描边，非命中且非祖先节点淡化（保持上下文不丢失）。
- 命中节点若位于折叠分支内会自动展开；右侧显示「当前/总数」并支持上下跳转。
- `Enter` / `Shift + Enter` 在命中之间循环，`Esc` 清除。
- **Review 模式**：点击 "Review" 按钮切换，只显示已标识（✅/❌/⏳）的节点及其祖先路径，其它节点直接隐藏（而非淡化），适合做 review 概览。可叠加关键词或状态 chip 进一步收窄。

### 4.7 三视图联动

| 触发 | 效果 |
|---|---|
| 源码光标移动 | 自动选中并定位对应导图节点 |
| 点击导图节点 / 标识节点导航 | 源码面板滚动并把光标定位到对应行 |
| 点击预览中的块元素 | 定位到对应导图节点 |
| 导图编辑/拖拽/标记 | 重新生成 Markdown 源码并刷新预览 |

联动策略低打断：只有目标节点不在可见区域时才自动拉回视图。

### 4.8 源码面板

三种模式（点击工具栏切换）：**源码** / **渲染** / **分栏**。

渲染支持：标题、段落、粗体/斜体/删除线、行内代码、代码块、链接、引用、有序/无序列表、任务列表、分隔线、表格。

分栏模式下，源码 textarea 与渲染预览**双向滚动同步**（按节点 lineIndex 锚点对齐），方便对照阅读长文档。

源码编辑快捷键：

| 快捷键 | 功能 |
|---|---|
| `Cmd/Ctrl + B / I / E` | 粗体 / 斜体 / 行内代码 |
| `Cmd/Ctrl + Shift + E` | 代码块 |
| `Cmd/Ctrl + K` | 链接 |
| `Cmd/Ctrl + Shift + 7 / 8 / 9` | 有序列表 / 无序列表 / 引用 |
| `Ctrl/Opt + 1~6` | 标题级别 |
| `Tab / Shift + Tab` | 缩进 / 反缩进 |

### 4.9 文件树管理

- 按文件夹层级展示，支持展开/收起、当前文件高亮。
- 新建文件、新建文件夹、删除（需浏览器文件系统写权限）、仅从浏览器移除（不删除磁盘文件）。
- 侧边栏收起/展开，宽度可拖拽调整。

### 4.10 保存与撤销

**自动保存**：有可写句柄时，最后一次变更后约 400ms 写回原文件。无可写句柄时保存到浏览器缓存，可手动下载。

**外部变更检测**：定时检查文件修改时间，磁盘更新后自动刷新内容；用户正在编辑时不会立即覆盖。

**撤销/重做**：按文件维护历史记录，最多 100 步，覆盖源码编辑、节点增删、状态标记和结构调整。

### 4.11 主题与偏好

- 亮色/暗色主题切换，状态持久化到 localStorage。
- 源码面板模式、浏览器项目快照同样持久化。
- 引入 Google Fonts 作为视觉增强，离线时降级为系统字体，不影响核心功能。

### 4.12 导出

工具栏的"导出"按钮提供三种格式：

- **导出 PNG**：将当前导图（含连线和节点样式）渲染为高分辨率 PNG，使用 SVG `foreignObject` + Canvas 实现，无外部依赖。
- **导出独立 HTML**：把当前 `md-mindmap.html` 与当前 Markdown 内容打包为一个独立 HTML 文件，离线双击即可重现当前状态，适合分享 review 结果。
- **下载当前 Markdown**：直接下载当前文件的 `.md`（保留所有状态 emoji 和节点备注）。

## 5. 当前限制

- Markdown 解析为内置轻量实现，不等同于完整 CommonMark 规范；复杂嵌套列表、HTML 混排、脚注、数学公式、Mermaid 暂未支持。
- 自动写回原文件依赖 File System Access API，主要适用于 Chromium 系浏览器。
- 单人本地工具，不支持多人实时协同。

## 6. 后续优化方向

**高优先级**
- 暂无（原有 4 项已全部完成，详见 §4.5 / §4.6 / §4.8）。

**中优先级**
- 自定义状态标签（如"新增""历史逻辑""阻塞"）— 当前只保留 ✅/❌/⏳ 三种内置状态，是否扩展待定。
- 暂无其他（多文件状态汇总、Review 摘要、导出（PNG / 独立 HTML / Markdown）、节点备注已全部完成）。

**低优先级**
- 更完整的 Markdown 语法兼容。
- 更丰富的布局方向和主题样式。
- 与 Git diff 结合，突出本次变更节点。

## 7. AI 代理服务（可选）

`ai-proxy.js` 提供本地 AI 代理，让模型在回答前按需检索本地 Markdown 内容，降低凭空生成的风险。

**知识源**
- 浏览器端正在编辑的 Markdown（由前端请求上下文传入）。
- 服务进程目录下递归扫描的所有 `.md` / `.markdown` 文件（自动忽略 `node_modules`、`.git`、`.idea`）。
- 同路径下浏览器版本优先于磁盘版本，避免重复。

### 7.1 工具清单

| 工具名 | 用途 | 主要参数 |
|---|---|---|
| `list_modules` | 递归列出子目录，支持分页 | `parent`, `offset`, `limit` |
| `list_files` | 列出 Markdown 文件，可限定目录，支持分页 | `module`, `offset`, `limit` |
| `search_keyword` | 大小写不敏感关键字搜索，命中按行返回 | `keyword`, `module`, `limit` |
| `read_file` | 读取单个文件完整正文（最多 120000 字符） | `path` |
| `read_file_lines` | 按行号区间读取文件片段（带行号） | `path`, `startLine`, `endLine` |
| `find_file` | 按文件名关键字查找文件，支持分页 | `module`, `keyword`, `offset`, `limit` |

### 7.2 运行参数

- 模型：`CONFIG.aiModel` 配置，默认 `gpt-5.5`。
- 请求地址：默认 `https://api.openai.com`，可通过 `OPENAI_BASE_URL` 指向兼容接口。
- 推理强度：`reasoning.effort = medium`，超时 45s，工具调用最多 10 轮。
- 上下文自动带入当前文件名、选中节点、最近对话历史和 Markdown 摘录。

### 7.3 HTTP 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/` 或 `/md-mindmap.html` | 返回前端页面 |
| `GET` | `/api/auth/check` | 检查登录状态 |
| `POST` | `/api/login` | 登录（默认关闭，设置 `CC_MD_MINDMAP_USER/PASSWORD` 后启用） |
| `POST` | `/api/logout` | 退出登录 |
| `POST` | `/api/ai-chat` | 一次性返回 AI 回复 |
| `POST` | `/api/ai-chat-stream` | SSE 推送（`status` / `text` / `tool` / `done` / `error`） |
| `POST` | `/api/trash` | 将文件或文件夹移到系统废纸篓（body: `{ "path": "..." }`） |

### 7.4 启动

**第一步**：在项目目录下创建 `.env` 文件，填入配置：

```dotenv
# 必填：OpenAI 或兼容接口的 API Key
OPENAI_API_KEY=sk-xxxx

# 可选：使用兼容 OpenAI Responses API 的服务地址（默认 https://api.openai.com）
OPENAI_BASE_URL=https://api.openai.com

# 可选：启用登录校验，两项同时设置才生效
CC_MD_MINDMAP_USER=your-user
CC_MD_MINDMAP_PASSWORD=your-password
```

**第二步**：运行部署脚本：

```bash
# macOS / Linux
bash deploy.sh
```

```cmd
# Windows（命令提示符）
deploy.cmd
```

启动后访问 `http://127.0.0.1:8787/` 即可使用。日志输出到 `ai-proxy.log`。
